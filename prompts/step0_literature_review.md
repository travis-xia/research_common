# 4. Directives & Constraints (纪律与硬性约束)

- **Core Directives (核心任务与执行规范)**:
  1. **先判定任务类型**：读评测代码，判断是「可验证答案型」（有标准答案 / 单测 / 精确匹配）还是「开放式裁判型」（LLM 裁判、rubric 或胜率打分）。两类的数据主线不同：前者以公开的大规模合成 / 蒸馏数据为主，后者以本地教师蒸馏为主、公开数据只提供 prompt。
  2. **调研数据候选（分数优先）**：搜寻数据集只服务于最终 benchmark 分数。按以下检索路线各走一遍，合并后再排序：
     - **按任务关键词检索**：数据集、论文、综述。
     - **沿强模型反查**：找出近 12–18 个月在同类任务上最强的开源模型（优先 ≤8B、从 Base 起训的），读其技术报告 / 模型卡的 post-training 数据章节，列出随模型开源或明确使用的 SFT / RL 数据集与子集。很多最强的数据是模型厂商随模型一起放出的，只按数据集关键词搜容易漏掉。
     - **沿代际追新**：对每个经典数据集，查有没有更新一代、在同一任务上与它正面对比并胜出的后继数据集（论文里通常会拿老数据集做 baseline）。默认新一代优先，除非有反证。
     - **逐个翻开放后训练数据的机构页**：用 HF API 按社区验证度列出持续开源后训练数据的机构的数据集，例如 `curl -s "https://huggingface.co/api/datasets?author=<org>&sort=likes&direction=-1&limit=100"`（也可 `sort=downloads`，或用 `search=<领域词>` 代替 `author`），org 例如 nvidia、allenai、open-thoughts、open-r1、HuggingFaceTB、a-m-team、Qwen、deepseek-ai 等。把与本任务领域对口的数据集全部列进候选池再筛。likes / 下载量高说明被社区大量复用和验证；新发布但几乎无人使用、也没有定量结果的数据放在后面。
  3. **数据集遴选特征**（用于排序；越多越好，第一条最重要）：
     - **可归因的直接证据**：数据集论文 / 数据卡报告了「用一个 ≤8B 的 Base 模型只在该数据上 SFT 后，在目标基准或同族基准上的分数」，且这个分数高。没有这类数字的数据集，排在有数字的之后。
     - **新一代教师**：答案由近一代强推理模型（R1 级长链推理模型）或 ≥32B 的强模型生成，而不是早期 GPT-3.5/GPT-4 时代的自举数据。
     - **规模与可筛选性**：十万到百万级，并带逐样本质量信号（同题多条回答、答案校验结果、单测执行通过率、LLM 打分等），方便后续只挑高分 / 最短正确样本。规模大不等于要全用，关键是能从中筛出高质量子集。
     - **题型同形（硬约束）**：主干数据的题型、难度必须与评测一致：评测是选择题，主干就必须是「选择题 + 推理轨迹 + 选项字母答案」的数据，且**选项数、学科范围与难度**也要和评测一致（例如评测是四选一，就优先四选一的数据，而不是十选一或开放式问答的后继版本），开放式问答 / 证明类数据只能做补充；评测是竞赛整数答案题，主干就是带可校验终答的竞赛题轨迹；评测是函数补全，主干就是带单测的函数级代码题。含有从目标基准**训练集**扩增出的子集的数据集额外加分。
     - **教师版本与同题多解**：证据和社区验证度相当时，优先由更新修订版推理模型生成的那一版（新修订版轨迹通常更短、正确率更高）；同题提供多条已校验回答的数据更好，可以只保留最短的正确轨迹。
     - **长轨迹数据的证据要看训练规模**：长链推理数据（单条数千 token 以上）在本预算内只能训练约 2–5 万条、1–2 个 epoch。若某数据集的亮眼分数来自百万级样本、多阶段 SFT 或 SFT+RL 的完整管线，在本预算下复现不了，要打折；优先选择在十万条以内的训练规模下就有公开 SFT 结果的数据（或作者报告了小规模子集结果的数据）。
     - **规模与长度适配预算**：4B 学生在单卡、十小时量级的预算内，实际只能训练数万条长轨迹。优先已经做过长度过滤（轨迹能在评测生成上限内写完）和正确性校验、规模在十万级以内的数据集，或者能低成本从中筛出这种子集的数据。百万级的混合数据（多领域混在一起、轨迹普遍超过评测上限）即使上限更高也排在后面，除非它提供了可以直接用来筛选的长度 / 难度 / 正确率字段。
     - **冷启动可落地性（决定第 1 位）**：第 1 位候选要作为 Golden Run 主干，在开局约 1 小时内完成下载、筛选与渲染。在满足题型同形的候选中，优先「下载即用」的形态：作者官方标注为 SFT 效果最好的精选子集、已做正确性校验、轨迹已按评测量级的长度上限生成、规模在十万条量级；本机 HF 缓存（`$HF_HOME/hub`）里已有的数据可直接复用，应先 `ls` 查看。需要从数百万条全集里自建多级筛选流水线才能用的数据，即使上限更高，也放在第 2 位作为后续扩展。可流式读取、按现成字段一步筛出目标子集的大数据集不受此限。
  4. **开放式裁判型任务的教师选型**（这类任务的核心数据就是教师）：至少列出 3 个候选教师，并写出各自在**目标基准本身**（或最接近的同源基准）上公开报告的分数，再按以下顺序选：
     - 单卡可部署：参考 `skills/engineering/env_and_hardware.md` 的显存；≤32B dense（可用 Int4/FP8 量化版）或总参 ~30B 级、激活参数小的 MoE。
     - 目标基准公开分数最高：模型卡或技术报告里直接报告该基准的模型优先；领域专精模型（如医疗、写作专项）常常胜过同尺寸通用模型，必须检索。
     - 风格与格式对齐：与基座同家族、最新一代、**非思考（不输出 think 块）**的 Instruct 版本更容易被学生模仿。
     - 生成吞吐：激活参数小的 MoE 能在有限时间内产出万级样本。
     - 公开数据集在这里主要提供 prompt 种子（真实用户意图分布、多语言覆盖），记录推荐的 prompt 来源与配比。
  5. **数据集可以混合使用**：冷启动可以用 2–4 个互补来源（也可以单个），按评测格式统一。若下载 HuggingFace 数据集，记得查阅快速下载指南 `skills/hf-download.md`。
  6. **调研训练范式**：搜寻该类任务有效的微调手段（SFT 数据配比、长链 CoT 引入、SFT+GRPO、on-policy DPO、权重平均、冷启动设置）。多参考高影响力、效果好的资料。通用超参见 `skills/post_train/recipe_guidelines.md`。
