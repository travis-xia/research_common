# 4. Directives & Constraints (纪律与硬性约束)

- **Core Directives (核心任务与执行规范)**:
  1. **深入剖析官方最新评测日志**：
     - 绝不凭空臆测！必须实地查看 `logs/` 下最新的评测逐题详细输出。
  2. **多维度细分现象与提取事实切片（下列四类分面每类都过一遍，重点展开命中的那类）**：
     - **(a) 子领域分面**：把任务切成子领域，看错误是否集中在某一类。数学切代数/几何/数论/应用题；科学题切物/化/生；代码切数据结构/字符串/数学。**分面依据必须可复现**（关键词、题干特征、已有元数据），不要人工主观打标，更不要调外部模型来打标。
     - **(b) 能力维度分面**：同一道题错在哪个环节——计算精度、逻辑规划（步骤顺序）、概念理解、格式遵循。
     - **(c) 过程检查**：不只看最终对错，更要看中间过程：
       - 正确答案其实已经出现在推理里，但最终答案栏写错/没被抽取到；
       - 自我修正后反而改错；
       - 复读、死循环、提前放弃；
       - 工具调用类任务：调用率、参数错误率、调用格式错误率。
     - **(d) 条件正确率**：同一模型在不同条件下的分层准确率——长回答 vs 短回答、题干长 vs 短、推理步数多 vs 少、是否触发截断、是否命中某个格式模板。**这类分面最容易直接指向一个操作空间坐标，性价比通常最高，优先尝试。**
     - **典型Case提取**：挑出2~3个最具代表性的失败样例作为后续假说的立论证据。
  3. **输出量化诊断与明确靶点**：
     - 诊断结论必须指向具体的瓶颈机制，并在 frontmatter 中给出推荐的修改坐标 `suggested_targets`。
     - 你的产物将被直接喂入下一轮 Hypothesis 生成节点。

- **Banned Actions (禁止项)**:
  - 严禁全局 `find /` 遍历扫描；清理进程必须基于 PID，严禁按字符串/进程名匹配误杀。
  - 严禁凭空臆测错误原因，分面依据必须有日志证据且可复现。
  - 严禁耗费过长时间做繁重训练或大实验，以阅读分析和快速切片验证为主。
