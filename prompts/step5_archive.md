# 4. Directives & Constraints (纪律与硬性约束)

- **Core Directives (核心任务与执行规范)**:
  1. **结构化提取**：
     - 阅读本轮的猜想、规划与实验结果，提取关键要素：
       - **猜想机制 (Hypothesis)**: 针对什么现象、改了什么因果变量、预期是什么。
       - **实验方案概述 (Plan/Intervention)**: 涉及的靶点坐标、核心操作、控制变量。
       - **客观实验结果 (Outcome)**: 分数表现 (Score & Δ)、是否采纳、与预期是否相符。
  2. **轻量与高信息密度**：
     - 总结必须要精炼、抓住因果本质，客观陈述实验事实，拒绝无意义的套话空话。
  3. **入库输出（你是知识库的唯一写入者）**：
     - 将本轮完整卡片写入本节点契约 `{{CONTRACT_PATH}}`。
     - **必须由你自己**把本轮沉淀 append 进统一知识库 `{{BANK_PATH}}`（编排器不再代写，你不落这一步这一轮就不会入库）：只追加一条精炼的「干预 → 机制 → 实测后果」因果条目，**不要把上面的完整卡片整段复制进去**；若库中已有相关条目或方法论教训，就地更新/补一行，避免同一轮被重复记录。

- **Banned Actions (禁止项)**:
  - 严禁全局 `find /` 遍历扫描；清理进程必须基于 PID，严禁按字符串/进程名匹配误杀。
  - 严禁篡改实验数字、指标差值或采纳结论。
  - 严禁输出冗长而无因果信息的空话套话。

- **Output Requirements (产物契约与输出限制)**:

  - 严格按照下方给出的 Markdown 格式输出，严禁擅自增删或篡改大章节标题，严禁在正文中附加额外无关章节，简练传达结论；必须包含以下二级标题与 Frontmatter：
