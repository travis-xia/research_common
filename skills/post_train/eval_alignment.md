# 评测对齐与防污染规范 (Eval Alignment & Decontamination)

## 何时查阅
- 在设计训练数据输入输出格式、对齐提示词模板、编写或审查数据清洗逻辑时。

---

## 1. 训练与评测输入输出四层对齐
训练样本的输入输出格式若与评测时评测器传入的格式不一致，会导致模型严重不适。必须保持四层一致：
1. **上下文层 (Context)**：
   - 评测中是否带有 System 提示词？带几条 Few-shot 示范？训练数据的 prompt 应保持相同上下文结构；全部带上开销过大时，至少一部分样本要带上（比例按 token 预算确定），不能全部按零样本渲染，也不要推迟到后续轮次。
2. **包装层 (Packaging)**：
   - 输入问题的包裹方式（如 `Question: ...\nAnswer:`）必须与官方评测脚本逐字对齐。
3. **正文层 (Body)**：
   - 期望的回答形态：是否包含分步推理（CoT）？是否要求用 `<think>...</think>` 标签？长度分布是否合理？
4. **收尾与终答层 (Ending)**：
   - 评测脚本的答案提取正则（如 `#### 123` 或 `\\boxed{123}`）决定了最终答案必须使用的标记。
   - 终答之后必须立即紧跟终止符，切勿在终答后追加冗余解释，否则提取器可能解析失败。训练目标的结尾形如「终答标记 + 立即停止符」（如 `ANSWER: <答案><|im_end|>`）。
   - **终答位于思考段之外**：带 `<think>…</think>` 的任务，终答行必须写在 `</think>` 之后。推理引擎的 reasoning parser 会把思考段剥离到独立字段，抽取器只解析其后的正文，写在思考段内的终答一律不计分。训练样本的终答位置需逐条校验。

### Loss 范围
- Prompt 部分 mask，只在 completion 上计算 loss。
- 多轮样本只在需要学习的 assistant 轮次上计算 loss（通常是最后一轮）。

### 落盘前校验
- 用评测的 chat template 渲染训练样本，与评测实际输入逐字节比对。
- 用评测的答案抽取逻辑对每条训练目标跑一遍，命中率应为 100%，且终答类型与评测一致。
- 只保留可验证正确的样本。
- 对数据做任何变换（重排选项、改写答案格式、截断等）后，抽样核对推理轨迹里引用的内容（如选项字母、中间结论）与新终答是否一致；不一致的变换不能用。

---

## 2. 数据防污染硬性约束
- **严禁泄漏测试集**：
  绝对禁止使用当前 Benchmark 的测试集数据进行训练，严禁从测试集具体题目进行文本改写、扰动或作为生成 Prompt。
- **运行查重脚本**：
  若环境中提供了 `contamination_check.py` 及相关测试集签名，必须在清洗数据后实际执行查重脚本，确保重合度为 0。
