# 训练方案设计参考 (Recipe Design Reference)

## 何时查阅
- Step0 制定主干配方，或 Step1/2/3 构思训练相关假设与实验方案时查阅。

---

## 0. 配方推导流程
1. **刻画任务**：依据 `research/protocol.md` 与基线实际输出，按 §2 的维度描述当前任务。
2. **读取诊断信号**：从基线/主干输出中统计 §3 列出的信号，确定主要丢分来源。
3. **组合干预包**：针对显著的失败模式，从 §3、§4 选取干预手段；§5 给出常见维度组合下的 Golden 默认取值，可直接作为 Golden 配方的起点。
4. **记录依据**：在决策卡中写明每项选择对应的维度取值或诊断信号（附实测数值），以及后续计划如何确认（§7）。

---

## 1. 正确性约束
以下条目决定评测能否正常计分，详见 `eval_alignment.md` 与 `inference_and_decoding.md`：
- **格式对齐**：训练样本与评测输入的四层结构逐字节对齐；结尾为「终答标记 + 立即停止符」（如 `ANSWER: <答案><|im_end|>`）；Prompt 部分 mask，只在 completion 上计算 loss。
- **终答位于思考段之外**：带 `<think>…</think>` 的任务，终答行必须写在 `</think>` 之后。推理引擎的 reasoning parser 会把思考段剥离到独立字段，抽取器只解析其后的正文，写在思考段内的终答一律不计分。训练样本的终答位置需逐条校验。
- **解码配置完整**：`generation_config` 中写全全部 EOS（如 Qwen `[151645, 151643]`），否则模型可能不停机；`max_new_tokens ≥ 评测上限`（基座默认的 2048 常不够）；四个采样键显式写全；保存后复核未被回退成基座默认值。部分推理引擎（如 vLLM）直接读取 `generation_config.json` 中的 `temperature`，目标温度需写入文件本身。
- **数据正确性**：只保留可验证正确的样本，终答类型与评测一致；完成去污染自查。
- **合规**：不调用外部商业闭源 API；在本地 GPU 上部署开源模型属于允许范围（§6）。
- **交付兜底**：尽早存一个可用的 `final_model`；下载/清洗与占卡训练并行。

## 2. 任务刻画维度
用以下相互独立的维度描述任务，配方由维度组合推导：

| 维度 | 取值示例 | 主要影响 |
|---|---|---|
| 输出契约 | 可程序校验的终答 / 可执行（单测、AST、JSON） / 裁判打分（rubric、成对胜率） | 数据过滤方式、是否适合 RLVR、解码温度 |
| 推理长度 / 生成预算比 | 短答、短 CoT / 长推理且接近预算上限 | 截断风险、长度门禁、`max_seq_len` |
| 对话结构 | 单轮 / 多轮（看评测实际轮数分布） | loss mask 范围、上下文合成方式 |
| 语种与约束分布 | 单语 / 多语；有无硬性正负向约束（字数、排版、禁用词） | 数据语种配比、约束合成 |
| 选项结构 | 无 / 固定选项字母 | 位置偏置、能否打乱选项 |
| 数据可得性 | 有原生训练集 / 需教师合成 / 需执行验证 | 蒸馏与过滤管线投入 |

同时满足多种取值时，优先满足更严格的输出契约。

## 3. 失败模式 → 诊断信号 → 干预手段

### 3.1 预算截断与复读循环
- **信号**：生成触及 `max_new_tokens` 且无终答标记的比例；尾部 n-gram 重复率；截断样本的长度分布。小模型在长推理、长文写作中此比例可能过半，是最先统计的信号。
- **干预**：
  - 蒸馏数据中同题只保留**最短的正确轨迹**，降低序列长度，避免模仿冗长模式。
  - 训练数据长度门禁：在评测预算下预留约 2k~3k token 缓冲（预算 16k 时截在约 13k），按长度分层抽样，剔除失控超长与复读样本。
  - 解码加入 `repetition_penalty`（取值见 §5），配合适度温度。在长推理与长文场景中，这一项能让截断率出现数量级下降，往往直接决定得分高低，Golden 中即应配置。
  - 长推理场景不用纯贪心（`temperature: 0.0` 易诱发局部死锁），采用 `temperature 0.6 / top_p 0.95 / top_k 20`。

### 3.2 收尾与格式抽取失败
- **信号**：抽取器失败率；终答后仍有多余输出的比例；停止符缺失率；终答写在思考段内的比例。
- **干预**：见 §1 格式对齐、终答位置与 EOS；训练目标统一以规范化终答收尾；结构化输出（fenced block、`<tool_call>`）与评测模板逐字节一致。

### 3.3 短答任务中的过度发散
- **信号**：错误样本中推理长度显著长于正确样本；算术/事实在中途漂移。
- **干预**：精炼短 CoT 或规划式分步解，不引入长 `<think>`；解码用纯贪心（`temperature: 0.0`）。

### 3.4 执行期失败（代码、结构化协议）
- **信号**：语法错误、缺少 import、签名不一致、类型错误、默认参数回显等的占比。
- **干预**：
  - **执行过滤**优先于堆量：对候选样本执行"抽取 → 拼装 signature/docstring → 编译/运行单测"链路，只保留通过者。约 20k~50k 条验证通过的样本优于数十万条未校验数据。
  - 优先选用带类型注解、标准 docstring、缩进规范的实现；工具调用数据过滤默认参数回显与类型不匹配样本。
  - 解码用纯贪心。

### 3.5 选项位置偏置
- **信号**：训练集与模型预测的选项字母分布，与均匀分布的偏差。
- **干预**：通过**下采样**平衡各选项分布。长推理轨迹中常已多次点名选项字母，直接打乱选项会造成轨迹与终答冲突，因此不打乱选项。

### 3.6 信息不足时武断作答、遗漏风险分流
- **信号**：裁判 rubric 各维度失分分布（澄清追问、风险/升级建议、事实严谨、约束遵循）。
- **干预**：见 §4.4 多轮合成与末轮重写；针对扣分最集中的维度定向注入补丁数据，总量约 1k~2k 条（如补齐免责声明/风险分流、追问澄清、特定格式遵循）。

### 3.7 语种与约束漂移
- **信号**：输出语种与输入语种不一致的比例；长输出中初始约束的违反率。
- **干预**：训练集语种配比对齐评测语种分布，不依赖英文自发泛化；合成带硬性正负向约束与结构约束的题目。

### 3.8 教师脚手架 / 元话语泄露
- **信号**：输出中出现"好的，为您……"等客套话、教师人设痕迹或 system prompt 内容的比例。
- **干预**：构造学生样本时剥离教师侧 system prompt 与所有元话语，只保留评测原生的 Input/Output 结构（见 §6.4）。

### 3.9 评测方差与选模
- **信号**：相邻 checkpoint 或不同种子间的分数波动；评测集规模。
- **干预**：
  - 长推理任务单题方差大，末期相邻 checkpoint 的权重平均可平滑波动，成本低，可直接纳入 Golden 交付（§4.5）。
  - 小规模评测集（如 30~50 题）不足以下结论，以全量统一尺子为准。
  - 知识密集的选项式任务例外：平均可能稀释高置信答案，此类任务以单模型交付，平均版本需在全量尺子上胜出才替换。

## 4. 训练范式与超参空间

### 4.1 主干目标
- **区分 baseline 与主干**：裸基座或极简 SFT 用作诊断参照；Golden 主干采用当前证据下预期得分最高的配方，不因"先跑通"而删掉教师造数、多轮数据、定向补丁等与瓶颈直接匹配的数据建设。
- **干预包可以是多组件的**：数据构造、训练目标与配套过滤/格式对齐只要共同服务同一瓶颈，就可以作为一个包。冻结的是与目标无关的变量（评测尺子、学生基座、协议、未声明超参等）。
- **蒸馏是一等数据策略**：开放式、rubric 评分、多轮或专业安全任务，显式考虑本地强教师生成、末轮重写、rubric-aware 筛选与 rejection sampling，并在数据卡中记录教师 provenance、去污染与过滤结果。
- **高风险优化器放在主干之后**：在线 GRPO、复杂 DPO、多轮 RL 依赖稳定的 SFT 主干，安排在 Golden 之后；若已有强证据表明它是当前最高收益路径，可以提前，但需说明预算、风险与回退方案。

### 4.2 全参 vs LoRA
- 目标涉及改变输出协议（停止符行为、回答结构、思考标签格式）或较深的推理能力提升时，用全参微调（bf16）；LoRA 可能因输出层/词表调整不足而在协议对齐上失效。默认为单阶段全参 bf16。
- 显存受限，或只在窄分布上做轻量模式注入（如答案直出）时，可用 LoRA/浅层 SFT，并监控格式遵循率。

### 4.3 超参区间
- **学习率**：全参 SFT `1e-5 ~ 2e-5`（代码类 `1e-5 ~ 1.2e-5`），Cosine 调度、约 3% warmup；LoRA `1e-4 ~ 2e-4`；RL 阶段约低一个数量级（`1e-6 ~ 3e-6`）；精选子集续训 `3e-6 ~ 4e-6`。
- **Epoch**：领域微调 1~2 个；高质量代码集上 1 个 epoch 已收敛大部分能力；多轮对话类 2 个为平衡点，3 个易对特定语调过拟合并损伤通用指令遵循。
- **长 CoT SFT 数据量**：主干建议 2 万~5 万条。小模型只在约 1 万条以下的长 CoT 上训练时，可能出现长链退化（冗长、复读、不收口），得分可能显著下降，需扩大数据量才能越过。
- **批次与吞吐**：有效 batch 16~64。有效 batch 定下后，per-device bs 从较大值（8 或 16）起步，真实 OOM 再减半并成倍增加 `gradient_accumulation_steps`；过小的 per-device bs 会浪费墙钟。
- **显存优化**：FlashAttention-2、Gradient Checkpointing；大词表（150k+）下使用 fused/chunked cross entropy（如 Liger Kernel，或只在被监督 token 上分块计算 loss）避免 logits OOM；可配合 8-bit AdamW 与序列打包（BFD packing）。
- **序列长度**：`max_seq_len` 由评测输入长度与生成上限之和反推（短答/代码 2048~4096，长推理 8192~16384），避免无意义 padding 或粗暴截断。

### 4.4 数据构造手段
- **训练数据与评测同形**：训练样本的任务形式、选项结构、终答位置与评测一致。选项式评测使用同类选项题的推理轨迹；开放式题目轨迹与短 rationale 切片不混入同一主干，否则模型在评测形状下会退化为浅推理或丢失终答格式。
- **同源数据与增广**：优先使用任务原生高质量训练集与同源增广；若评测带特定 system prompt 或 few-shot 约定，按约 10%~15% 比例混入相同 prompt 结构，对齐零样本与少样本条件。
- **长推理蒸馏**：从强推理模型蒸馏带完整反思链的轨迹，完整保留 `<think>…</think>` 标签，配合 §3.1 的最短正确轨迹与长度门禁。
- **答案直出**：收集多源高质量题目（约 20k~30k 条），监督目标直接设为最终答案；耗时短、显存省。适用于长链难以驾驭或墙钟不足以完成蒸馏的情况。
- **多轮情境网格合成**：用 30B 级教师按"主题 × 人设 × 语言 × 场景 × 意图转折"网格合成上下文，轮数分布对齐评测样本。前序助手轮保留普通水平或轻微瑕疵，还原真实历史。
- **末轮重写与自审**：末轮回答由强教师按评分维度生成，再执行一轮自审与专业细节补全（如具体警示征象、干预建议、求助/就医指引），提高信息密度。
- **多轮 loss 范围**：只在最后一轮 assistant 上计算 loss，不在模拟的弱历史轮上计算，避免学到低质表达。
- **脱壳蒸馏**：教师在强人设 system prompt 下生成正文，学生样本中剥离该 prompt 与元话语（§3.8）。

### 4.5 SFT 之后的优化手段
- **RLVR / GRPO**：适用于真值可程序判定的任务。先用 SFT 模型自采样，筛出通过率处于约 0.2~0.8 的题目展开训练，可带来数个百分点的增益。长推理场景下 RL 与二阶段长链续训易发散，需要充足算力与高覆盖采样，否则以单阶段 SFT + 末期平均为主交付。
- **RFT / Rejection Sampling**：SFT 后用模型自身多路采样（如 k=8），程序化校验保留正确且多样的路径，混入后续训练。
- **On-policy DPO**：对 SFT 模型多路采样，按评分维度构造成对样本（啰嗦截断、漏澄清、漏风险分流作 rejected），低学习率训练 1 轮左右；轮次过多或高频自蒸馏会损伤多样性。裁判打分常饱和在窄高分区间，相对比较（同一 prompt 采约 4 个候选，选出相对最优与最劣）比绝对打分更有区分度。
- **权重平均 / 插值**：
  - 末期相邻 2~3 个 checkpoint 均匀平均，平滑长推理评测波动。
  - SFT 与 DPO/GRPO checkpoint 平均（`0.5 · SFT + 0.5 · DPO`）：前者擅长专业细节，后者擅长边界与格式遵循，混合后常优于任一单模型。
  - 两阶段插值：先在大底座数据上训 v1，再在高置信、零污染精选子集上用小学习率续训 v2，按 `0.625 · v1 + 0.375 · v2` 插值，可中和边界用例的单题波动。

## 5. 常见维度组合下的 Golden 默认取值
任务符合某一行的维度组合时，Golden 配方直接采用该行默认值；"后续阶段"列为 Golden 之后的演进方向。任务不完全匹配时，按维度逐项拼装。

| 维度组合 | 待统计信号 | Golden 默认 | 解码默认 | 后续阶段 |
|---|---|---|---|---|
| 可校验终答 × 长推理接近预算 × 单轮 | 截断率、复读率 | 长推理蒸馏 + 最短正确轨迹 + 13k 长度门禁；全参 SFT，`ctx 16384`；末期 2~3 个 checkpoint 均匀平均作为交付 | `T 0.6 / top_p 0.95 / top_k 20`，`repetition_penalty 1.03~1.05` | 充裕算力下再考虑 RL |
| 可校验终答 × 短推理 × 单轮 | 过度发散、收尾失败 | 原生训练集 + 同源增广 + 短 CoT；10%~15% 混入评测 prompt 结构；全参 SFT 1~2 epoch | 纯贪心 `T 0.0` | 中等通过率题目上做 GRPO；SFT 与 GRPO 平均 |
| 可执行 / 结构化 × 短中长度 | 执行期失败、抽取失败 | 执行过滤数据 20k~50k；全参 SFT 1 epoch，`lr 1e-5`，`ctx 2048~4096` | 纯贪心 `T 0.0` | 精选子集小步长续训 + `0.625·v1 + 0.375·v2` 插值 |
| 可校验终答 × 固定选项 × 高难专业知识 | 截断率、位置偏置 | 长 CoT 蒸馏 + 最短正确轨迹 + 选项下采样平衡（不打乱）；单模型交付 | `T 0.6~0.9`，`repetition_penalty 1.05~1.06` | 截断仍高或墙钟不足时切换答案直出（短答案模式用纯贪心） |
| 裁判 rubric × 多轮 × 风险敏感 | rubric 各维度失分 | 网格合成多轮（前序轮带瑕疵）+ 末轮重写自审 + 1k~2k 定向补丁；只算末轮 loss；全参 SFT 2 epoch | `T 0.0~0.3` | On-policy DPO + `0.5·SFT + 0.5·DPO` 平均 |
| 成对胜率 × 长文 × 多语言/强约束 | 截断率、语种漂移、元话语泄露 | 脱壳蒸馏 + 语种配比对齐 + 显式约束合成；全参 SFT | `T 0.7~0.8 / top_p 0.8~0.9 / top_k 20`，`repetition_penalty 1.05` | 成对比较构造 DPO，1 轮低学习率 |

## 6. 本地算力数据生产 (On-Device Data Generation)

### 6.1 边界
- 不调用任何外部商业闭源 API。
- 允许在当前任务分配的本地 GPU 上部署开源强模型做离线数据生产与处理。开放长文、多轮对话、高难推理等任务中，这是提升数据质量的常规手段。

### 6.2 选型与部署
- 优先考虑 Qwen 系列 30B 级 FP8 官方量化版本（参见 [Qwen HuggingFace Collections](https://huggingface.co/Qwen/collections)），单张 H100/A100 即可拉起，吞吐高；推理类数据用 Thinking/推理版，对话与写作类用 Instruct 版；垂直领域可选已验证的同量级领域模型。
- 使用高性能推理框架（vLLM 离线 `LLM.generate` 或本地 HTTP 服务），避免原生 PyTorch 逐条前向。

### 6.3 生产范式
- **长文写作**：教师挂载人设与结构要求的 system prompt，对清洗去重后的多语言种子 prompt 批量生成；学生采样多候选后由本地教师做成对比较，产出 DPO 数据。
- **多轮对话**：按网格自动生成带轻微瑕疵的历史上下文；末轮先生成初稿，再由模型自审补全。
- **推理任务**：本地推理模型生成完整反思链解答；SFT 后用学生模型高并发多路采样做 rejection sampling。

### 6.4 数据门禁
- **脱壳清洗**：落盘前剥离生产用的临时 system prompt、引导语与客套话，只保留评测原生 Input/Output 结构。
- **真值校验**：有确定真值的任务（代码、数学、结构化输出），每条候选需通过单测执行、AST 解析或严格数值比对。
- **长度门禁**：统计 token 分布，丢弃触及生成上限或局部复读的样本。
- **分布平衡**：检查选项、语种、答案格式分布，必要时下采样消除生成偏置。
