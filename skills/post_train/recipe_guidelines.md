# 训练方案与超参指南 (Recipe Guidelines)

## 何时查阅
- 在 Step0 汇总输出主干配方，或 Step2/3 构思训练相关的猜想与实验方案时，重要参考经验。

---

## 1. 训练范式选择
- **全参微调 vs LoRA/QLoRA**：
  - 若目标涉及“改变输出协议（如停止符行为、回答结构、思考标签格式）”或“深度任务推理能力提升”，优先采用全参微调（Full-parameter fine-tuning, bf16）。LoRA 常因未能充分调整词表/输出层而在协议对齐上失效。
  - 若显存受限或仅在极窄分布上做轻量模式注入，可使用 LoRA，但需密切监控格式遵循情况。
- **单阶段 vs 多阶段**：
  - 优先以稳定、高质量的 SFT 建立基准主干。
  - 在奖励函数高度明确、可程序化自动化验证（如数学终答、单元测试通过率）时，完全可以考虑引入 RL（比如GRPO） 阶段，使得模型收敛到正确分布。

---

## 2. 常用超参基准范围（经验先验）
- **学习率 (Learning Rate)**：
  - 全参 SFT：通常推荐在 `1e-5` 到 `2e-5` 之间，配合 Cosine 调度器与 3% Warmup。
  - LoRA：通常在 `1e-4` 到 `2e-4` 之间。
  - RL 阶段：学习率通常比 SFT 低一个数量级（`1e-6` 到 `3e-6`）。
- **训练轮数 (Epochs)**：
  - 绝大多数特定领域微调推荐 1 ~ 2 个 Epoch。
- **批次大小与吞吐优化（先大后小、爆显存再减半）**：
  - 有效 Batch Size 建议保持在 16 ~ 64。
  - **per-device bs 先大后小**：effective batch 定了之后，单卡批次（per-device bs）往大试（如从 8 或 16 起步），**真实爆显存（OOM）再减半**并成倍增加梯度累积步数（gradient_accumulation_steps）以补齐有效 batch。
  - 严禁凭空盲目把 bs 压得极小（吞吐大幅下降白白烧墙钟）。
  - 尽可能启用 FlashAttention-2 与 Gradient Checkpointing，词表大时使用 fused/chunked cross entropy 避免 logits OOM。
- **序列长度**：
  - `max_seq_len` 应根据目标任务协议的实际输入长度与最大生成上限总和反推，避免无意义的过大 padding 或粗暴截断。

## 3. 黄金初始策略示例（Golden Initial Strategy · 起手配方）

Step0黄金起手的核心原则是**先用最稳的配方跑通拿到基线，再谈改进**。以下先给不分任务的普适内核，再按任务形态、输出契约和失败模式路由需要调整的旋钮。

### 3.1 普适内核（任何任务都照做）
- **范式**：单阶段全参微调（bf16），不要 LoRA/QLoRA。
- **格式对齐**（详见 `eval_alignment.md`）：训练样本与评测输入四层结构逐字节对齐；结尾固定「终答标记 + 立即停止符」（如 `ANSWER: <答案><|im_end|>`）；用 completion-only loss。
- **解码 `generation_config`**（详见 `inference_and_decoding.md`）：双 EOS 写全（如 Qwen `[151645, 151643]`），否则模型不停 → 0 分；`max_new_tokens ≥ 评测上限`（删掉基座默认 2048）；四采样键显式写全；存后复核未被回退成基座默认。
- **数据底线**：只留 verified-correct 样本、终答类型与评测一致；**务必对测试集做 8-gram/n-gram 去污染至重合度 0**（下面选数据的前提）。
- **流程纪律**：尽早存一个可用 `final_model` 兜底；下载/清洗与占卡训练并行；更长 trace、多阶段、RL 等改动**必须在 dev 上打过基线 SFT 才保留，打不过一律回退**。

### 3.2 按任务形态与失败模式分类讨论（据此路由起手配方）
先不要按 benchmark 名称选配方，而要根据**输出契约、评测器行为、答案长度和主要失败模式**路由到下列类别。一个任务只要满足某类的描述，就应优先采用该类的黄金起手；若同时满足多类，按更严格的输出契约优先，并在 dev 上做小规模 A/B。

**A. 数学难题 / 长推理（竞赛级数学、复杂多步推理与证明等）**
- **思维链**：蒸馏高质量**长思维链**，保留 `<think>…</think>` 标签（默认模板可能剥离，需手动保住）；同题多条正确 trace 时**取最短的正确 trace**并截到评测生成上限内。
- **序列长度**：适当取长，如`max_seq_len 8192~16384`，可以尝试**筛掉少量（数量不多的话）超长的**以降低序列长度先训练一个更大数据量、更高batch size的版本。
- **数据来源**：去污染前提下，优先**分布相近的高质量推理蒸馏集**（偏竞赛 / 奥赛级难题），规模约 **12k–32k 条**，数据尽量不要太少，可以从其他方面提高效率。
- **头号失败模式＝截断**：模型常话痨/复读/绕圈撑满上限却没吐出终答。对抗三板斧：最短正确 trace + `repetition_penalty 1.05` +（必要时）贪心；仍严重则追加一段更短更精炼的 SFT。
- **采样**：长 CoT 贪心易死循环，可用轻随机（如 Qwen3 thinking `temp 0.6 / top_p 0.95 / top_k 20`）。
- **RL**：时间/算力有限时收益有限，酌情。

**B. 数学简单题 / 短答案（基础应用题、格式化短输出等）**
- **思维链**：用**简短、有格式、有规划**的分步解题即可，**不需要长 `<think>`**，结尾直接 `ANSWER: <答案>`；过度冗长反而有害。
- **序列长度**：取短，`max_seq_len 1024~4096`，避免无谓墙钟。
- **数据来源**：去污染前提下，**先查看有无任务自身的官方训练集或相近题目**（官方 train 集 + 同源增广 / 改写数据），不必硬凑竞赛级数据；规模可更宽（数千原始 + 同源增广到数万）。
- **失败模式≠截断**：答案短、几乎不触顶；真正问题是「不停 / 跑题」，靠双 EOS + 贪心解决，一般**不需要 `repetition_penalty`**。
- **采样**：贪心（`temp 0`）即可，通常最稳。
- **RL**：奖励可程序化验证时 **RLVR/GRPO 收益大**（SFT 到瓶颈后常能再显著提点），值得在 SFT 后接一段。

**C. 可执行程序合成 / 单函数代码补全**
- **先做评测器镜像**：不要把“能生成代码”当作样本合格。对每条候选样本执行真实的 `抽取 → 拼回原始 signature/docstring stub → parse/compile → 单测` 流程；有单测时必须真实执行通过。
- **训练目标**：单个 fenced Python block，目标函数是第一个顶层函数；完整复述 signature 和 docstring；4 空格缩进；顶层 import 尽量移入函数体，helper 放进函数体或目标函数之后；去掉冒号后的尾随空白，避免抽取器匹配失败。
- **格式**：严格复现评测 chat template，prompt 全 mask，只对 assistant completion 计算 loss；completion 以代码块和正确 EOS 结束。训练表示要与评测器的代码抽取规则逐字节兼容。
- **数据**：优先 20k~60k 条执行验证过的单函数样本，混合带单测的指令数据与高质量函数实现数据；去重、去污染、记录每条样本的 parse/compile/test 状态。数据量不如可执行验证重要。
- **训练**：全参 bf16 SFT，通常 `max_seq_len=1024~2048`、1~2 epoch、`lr=1e-5~1.5e-5`、cosine + 3% warmup、FlashAttention-2；大词表造成 logits OOM 时用 chunked/fused cross entropy，不要为了省显存退化成未经验证的极小 batch。
- **解码与选模**：优先 greedy，显式写双 EOS 和足够大的 `max_new_tokens`；在原始 grader 的 full/大样本配置上选 checkpoint。DPO、RFT、model soup 只能作为第二阶段候选，必须超过第一阶段 SFT 才保留。
- **路由信号**：如果错误主要是代码块抽取失败、`NameError`、compile/test 失败，优先修数据门禁和格式，不要先增加训练轮数。

**D. 选项式专业知识 / 科学推理**
- **识别方式**：输入由问题和固定数量的选项组成，评分只看最终选项字母或短标签；中间可以有解释，但不能改变选项编号、字母或题目顺序。
- **数据格式**：用评测时的真实 prompt 和 chat template 重渲染训练集；目标为“可选的简洁或完整推理 + 最终 `ANSWER: <选项>`”；答案位置 A/B/C/D 必须均衡。若推理会引用选项字母，禁止随意做选项置换增强。
- **数据**：优先 20k~50k 条去污染的科学/专业四选一推理样本；保留 verified-correct、语言与选项结构完整的样本。应按轨迹长度分层，而不是无条件堆长 R1 trace。
- **默认起手**：对能稳定产生 reasoning 的模型，先用中等长度正确 CoT 做 completion-only 全参 SFT，`max_seq_len=4096~6144`；对小模型、预训练底座或明显长思维发散的模型，先用 concise-CoT/直接答案做 100~200 题 A/B，再决定是否引入长 CoT。
- **解码**：把“无最终答案/16k 截断率”作为一等指标。可先 sweep `temperature=0` 与 `0.7~0.9`；只有在重复推理明显时再试 `repetition_penalty≈1.05~1.06`，不要默认加惩罚。所有采样键写入 `generation_config.json`。
- **评测纪律**：小子集只用来发现格式和截断问题，不能用来宣布胜负；至少对 top-2 候选跑完整评测，并同时记录 accuracy、parse/answer rate、truncation rate 和 A/B/C/D 分布。
- **第二阶段**：若 SFT 后仍大量“不出答案”，优先做短轨迹 on-policy rejection sampling / RFT；DPO 只有在偏好信号稳定、全量评测确认提升时才加入。

**E. 多轮专业、安全、健康或风险敏感回答**
- **识别方式**：输入包含多轮 user/assistant 历史，最后一轮要求结合上下文回答、追问澄清、风险分流、格式约束或资源条件；评分关注完整性、上下文意识、沟通质量、指令遵循和安全边界，而不是单个事实 token。
- **数据结构**：构造 5~11 条消息的真实多轮上下文；中间 assistant 可以短、一般或不完整，模拟真实历史，最后一轮 assistant 才放高质量完整答案。覆盖澄清问题、风险提示、紧急分流、多部分约束、不同受众和不同语言/资源条件。
- **监督范围**：严格使用目标模型的 chat template，通常只对**最后一个 assistant turn**计算 loss；不要让模型把历史中的弱回答当作最终答案模仿。教师可以用 thinking mode 生成，但默认剥离不可见思维，只训练最终可见回答。
- **数据量与训练**：先做 7k~25k 条高质量多轮 SFT，2 epoch 作为起点，3 epoch 前必须检查过拟合；全参 bf16、FlashAttention-2、completion-only。真实用户 prompt 可作 seed，但参考答案必须重写/蒸馏并经过结构、语言、长度和安全过滤。
- **第二阶段**：SFT 后针对“截断长篇、缺少澄清、漏掉安全分流、没有遵守格式”的 on-policy 输出构造 preference pairs；可尝试一轮低学习率 DPO，再与 SFT 做 `0.5/0.5` 权重平均，但必须在至少 128 条和 full 评测上同时确认收益。
- **解码**：短而稳的专业回答通常从 `temperature=0~0.3` 起扫；若任务需要自然表达或多语言写作，再在 dev 上尝试 `0.6~0.9`。双 EOS、最大生成长度和拒答/分流模板必须端到端验证。
- **路由信号**：若模型知识不差但上下文利用、风险判断或多部分指令遵循差，优先增加多轮结构和 targeted patch 数据，不要盲目增加单轮问答数量。

**F. 开放式、强约束写作与风格遵循**
- **识别方式**：答案没有唯一 token 级真值，评分由 judge 或 rubric 综合语言、体裁、长度、语种、结构、风格和用户约束；“写得像”不等于“满足要求”。
- **数据**：以真实用户写作请求为 seed，覆盖语言、体裁、长度、受众、语气、格式和显式约束；优先使用本地强教师蒸馏，再过滤语言不匹配、拒答、元话语、截断、重复和约束遗漏。通常先准备 10k~25k 条去污染 SFT 样本，弱势语言和少见约束要定向补齐。
- **蒸馏规则**：教师 system prompt 默认不进入学生上下文；学生只看到评测时会看到的 user/chat 内容。训练目标应是完整、自然、符合约束但不过度灌水的 assistant completion。
- **训练**：全参 bf16、exact chat template、completion-only；`max_seq_len=4096~8192`，`lr≈1.2e-5~1.5e-5`，2 epoch 起步，保留 epoch-1/2 并检查过拟合。必须把 EOS 和 assistant turn 边界当作训练目标的一部分。
- **偏好优化**：可对每个 prompt 采 4 个候选，由强教师按“语言匹配 > 指令遵循 > 完整性 > 文采”排序，保留分差明显的 best-vs-worst pairs；DPO 建议一轮、低学习率、`beta≈0.1`。第二轮 DPO、RAFT 或无验证的 model soup 默认不启用。
- **解码与选模**：从 `temperature=0.7~0.9`、`top_p=0.8~0.95`、`top_k=20~64` 起扫，保留最符合 judge rubric 且重复评测稳定的配置；不能把单次 32/64 题峰值当结论，至少用 128~250 条或多次重复评测选模。
- **路由信号**：若主要问题是语言不一致、漏约束、过度解释或风格漂移，优先做分层 seed/教师过滤和 preference pairs；若主要问题是知识事实或格式错误，应回到前面的专业 QA / 格式对齐类别。
