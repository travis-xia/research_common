# 训练方案设计方法 (Recipe Design Method)

## 何时查阅
- Step0 制定主干配方，或 Step1/2/3 构思训练相关假设与实验方案时查阅。

---

## 1. 决定分数的优先级
按影响从大到小投入：
1. **数据选对**：主干数据与评测同形。来源与排序以 `research/literature.md` 第 1 节为准。
2. **数据量合适**：按 §3 反推本预算可训练的条数，再与 literature 第 3 节的规模证据取交集。
3. **数据生成方式选对**：公开数据里没有现成的高质量答案时（开放式、裁判打分任务常见），按 literature 反查到的方案在本机生成。
4. **评测对齐与解码**：决定能否计分，见 `eval_alignment.md` 与 `inference_and_decoding.md`。
5. **针对性方法**：只在 §4 的信号显著时启用，做法与数值取 literature 第 3、4 节。

---

## 2. 数值从证据中来
每个数值注明来源：本 run 实测、literature 出处或预算推导，不凭印象填写。没有来源时：
- **低成本参数**（解码参数、epoch、checkpoint 选择与合并）：训练后在尺子子集上对比几档取优。epoch 用一次训练、逐 epoch 存 checkpoint 的方式比较。
- **高成本参数**（学习率、数据规模与配比）：取条件最接近的公开证据，给出单一取值。学习率要连同有效 batch、总步数一起借；与本 run 相差一个数量级以上的证据不直接照搬，改用条件更接近的证据。

---

## 3. 预算可行域
- `max_seq_len` = 评测输入长度 + 生成上限。
- 可训练 token 数 ≈ 训练窗口（秒）× 吞吐（token/s）。吞吐以 smoke 实测为准；开工前可按「训练 FLOPs ≈ 6 × 参数量 × token 数」与显卡算力粗估。
- 可训练条数 = 可训练 token 数 ÷ 过滤后样本的平均 token 数 ÷ epoch 数。训练窗口要扣掉数据准备、导出、评测与一次失败重跑的时间。
- 但不得过于保守，在合适的范围内尽量追求充分数据训练、对模型的高提升，否则浪费算力。
- 可以通过一些方法尝试提升训练吞吐。

---

## 4. 必看的信号
- **截断与复读**：触及生成上限且没有终答的比例、尾部重复率。基线截断率不代表训练后的行为，训练后要重新统计。
- **格式与抽取**：抽取失败率、终答写在思考段内的比例。
- **答案分布**：选项类任务看训练集与模型预测的字母分布。
- **裁判维度失分**：rubric 类任务看各维度的失分分布。
- **评测方差**：分差小于标准误时不下结论。

---

## 5. 决策卡
每项主要选择写明：依据（信号与实测数值）、数值来源、确认计划（已在尺子上对比，或安排到后续节点）。
