# 训练方案与超参指南 (Recipe Guidelines)

## 何时查阅
- 在 Step0 汇总输出主干配方，或 Step2/3 构思训练相关的猜想与实验方案时，重要参考经验。

---

## 1. 训练范式选择
- **全参微调 vs LoRA/QLoRA**：
  - 若目标涉及“改变输出协议（如停止符行为、回答结构、思考标签格式）”或“深度任务推理能力提升”，优先采用全参微调（Full-parameter fine-tuning, bf16）。LoRA 常因未能充分调整词表/输出层而在协议对齐上失效。
  - 若显存受限或仅在极窄分布上做轻量模式注入，可使用 LoRA，但需密切监控格式遵循情况。
- **单阶段 vs 多阶段**：
  - 优先以稳定、高质量的 SFT 建立最优高分基准主干。
  - 在奖励函数高度明确、可程序化自动化验证（如数学终答、单元测试通过率）时，完全可以考虑引入 RL（比如GRPO） 阶段，使得模型收敛到正确分布。

---

## 2. 常用超参基准范围（经验先验）
- **学习率 (Learning Rate)**：
  - 全参 SFT：通常推荐在 `1e-5` 到 `2e-5` 之间，配合 Cosine 调度器与 3% Warmup。
  - LoRA：通常在 `1e-4` 到 `2e-4` 之间。
  - RL 阶段：学习率通常比 SFT 低一个数量级（`1e-6` 到 `3e-6`）。
- **训练轮数 (Epochs)**：
  - 绝大多数特定领域微调推荐 1 ~ 2 个 Epoch。
- **批次大小与吞吐优化（先大后小、爆显存再减半）**：
  - 有效 Batch Size 建议保持在 16 ~ 64。
  - **per-device bs 先大后小**：effective batch 定了之后，单卡批次（per-device bs）往大试（如从 8 或 16 起步），**真实爆显存（OOM）再减半**并成倍增加梯度累积步数（gradient_accumulation_steps）以补齐有效 batch。
  - 严禁凭空盲目把 bs 压得极小（吞吐大幅下降白白烧墙钟）。
  - 尽可能启用 FlashAttention-2 与 Gradient Checkpointing，词表大时使用 fused/chunked cross entropy 避免 logits OOM。
- **序列长度**：
  - `max_seq_len` 应根据目标任务协议的实际输入长度与最大生成上限总和反推，避免无意义的过大 padding 或粗暴截断。

---

## 3. 黄金初始策略示例（Golden Initial Strategy · 起手配方）

Step0黄金起手的核心原则是**先用最稳的配方跑通拿到基线，再谈改进**。以下先给不分任务的普适内核，再按任务形态、输出契约和失败模式路由需要调整的旋钮。

### 3.1 普适内核（任何任务都照做）
- **范式**：单阶段全参微调（bf16），不要 LoRA/QLoRA。
- **格式对齐**（详见 `eval_alignment.md`）：训练样本与评测输入四层结构逐字节对齐；结尾固定「终答标记 + 立即停止符」（如 `ANSWER: <答案><|im_end|>`）；用 completion-only loss。
- **解码 `generation_config`**（详见 `inference_and_decoding.md`）：双 EOS 写全（如 Qwen `[151645, 151643]`），否则模型不停 → 0 分；`max_new_tokens ≥ 评测上限`（删掉基座默认 2048）；四采样键显式写全；存后复核未被回退成基座默认。
- **数据底线**：只留 verified-correct 样本、终答类型与评测一致；。
- **流程纪律**：尽早存一个可用 `final_model` 兜底；下载/清洗与占卡训练并行；更长 trace、多阶段、RL 等改动**必须在 dev 上打过基线 SFT 才保留，打不过一律回退**。

### 3.2 按任务形态与失败模式分类讨论（据此路由起手配方）
先不要按 benchmark 名称选配方，而要根据**输出契约、评测器行为、答案长度和主要失败模式**路由到下列类别。一个任务只要满足某类的描述，就应优先采用该类的黄金起手；若同时满足多类，按更严格的输出契约优先，并在 dev 上做小规模 A/B。

**A. 复杂多步推理与数学难题（长思维链、奥赛与竞赛级推导）**
- **任务形态与丢分本质**：
  - 题目难度极高、步骤繁复，依赖深度的自我反思与多步纠错（如 `<think>…</think>` 模式），结尾提取严格格式的最终答案。
  - **核心致死陷阱是“预算截断（Truncation）”**：小模型（4B）在超长推理链条中极易陷入循环自证或无效绕圈，耗尽评测生成预算（如 16k tokens）而未能产出终答，直接被判 0 分。
- **数据选择与蒸馏策略（最短正确轨迹原则）**：
  - **同题取最短正确轨迹**：从顶尖推理模型（如前沿 R1 轨迹）蒸馏题解，一题多解时**务必只保留长度最短的正确解**；不仅能成倍降低序列长度与墙钟耗时，更能从根源上遏制模型模仿话痨式废话。
  - **留足推理预算冗余**：根据评测生成上限（如 16k）设定严格的数据长度门禁（预留 2k~3k token 缓冲，训练数据截断在 13k 左右），并按长度分层抽样，剔除失控超长样本。
  - 必须完整保留 `<think>…</think>` 标签，训练与评测提示词、终止标记逐字节对齐。
- **训练目标与进阶演进**：
  - **显存与超大词表应对**：全参 bf16 微调，`ctx=8192~16384`。针对大词表（如 150k+）容易引发的 logits 显存溢出，务必启用 FlashAttention-2、Liger Kernel（Fused Cross Entropy）或 Chunked Loss（仅在被监督 token 上分块计算 loss），配合 8-bit AdamW 与序列打包（BFD Packing）。
  - **末期模型融合（Checkpoint Soup）**：长推理模型的单题评测方差较大，训练收尾时选取最后 2~3 个相邻 Checkpoint 进行均匀权重平均（Model Soup），在实践中能有效平滑推导波动，提升最终通过率上限。
  - 多阶段与 RL 需克制：长推理场景下，若无极充裕算力与高覆盖率采样，复杂的二阶段长链续训或 RL 极易导致训练发散与崩溃，优先以极致打磨的单阶段 SFT + Soup 作为主交付。
- **解码参数配置（防僵死与兼顾多样性）**：
  - **避免纯贪心死循环**：在超长推导中，纯贪心（`temperature: 0.0`）极易诱发局部语义死锁与重复；推荐使用轻微随机的温和采样（`temperature: 0.6`、`top_p: 0.95`、`top_k: 20`），并显式写全双 EOS。
  - 若评测出现局部循环复读，可微调 `repetition_penalty ≈ 1.03~1.05`，遏制单一死胡同空耗 token。

**B. 确定性推理与短答案（基础应用题、格式化短计算）**
- **任务形态与丢分本质**：
  - 题目包含确定性事实推演或有限步算术计算，最终输出单一数值或规范短标签。
  - 核心丢分点通常**并非预算截断**，而是“过度发散导致的低级算术偏离”或“未能在正确位置收尾停机”；若盲目套用冗长思考链，反而会显著放大幻觉与漂移。
- **数据选择与构建策略**：
  - **精炼短 CoT / 规划式分步解题**：采用紧凑、有逻辑的分步解析，不盲目追求长 `<think>` 标签，结尾直接硬性规范化输出（如 `ANSWER: <答案>`）。
  - **同源增广与环境条件对齐**：优先利用任务原生高质量训练集及同源数据增广；若评测环境存在特定的 System 提示词或 Few-shot 约定，可在训练集中按比例（约 10%~15%）混入相同 Prompt 结构，促成零样本与少样本环境的条件对齐。
- **训练演进：SFT → RFT / RL 闭环升阶**：
  - **第一阶段（稳健基线 SFT）**：全参 1~2 epoch 建立基本算术推理与格式规范。
  - **第二阶段（可验证真值下的 RL / GRPO 收益最大化）**：此类任务具有极明确、可自动化判定的真值（Ground Truth），是应用强化学习（如 GRPO / RLVR）的最佳阵地。
    - 实践中可先用 SFT 模型自我采样，筛选出模型尚未完全饱和（Pass Rate 在 0.2~0.8 之间）的题目重点展开 RL，能带来数个百分点的纯增益。
  - **收尾交付**：将 SFT 与稳定迭代的 GRPO Checkpoint 进行权重平均（Soup），中和策略漂移风险。
- **解码参数配置（确定性第一）**：
  - **坚决采用纯贪心（`temperature: 0.0`）**：确定性应用题不需要发散思维。特别注意：若使用 vLLM 等推理引擎，其可能忽略外层采样开关而直接读取 `generation_config.json` 中的 `temperature`（基座常默认为 1.0）；务必显式将 `temperature: 0.0` 写入配置文件，避免高随机性吞噬精度。
  - 显式写全双 EOS 终止符，防止多余输出。

**C. 可执行程序合成 / 单函数补全与严苛结构化输出**
- **任务形态与丢分本质**：
  - 评测不靠主观打分，而是硬性的**沙箱执行测试（如 pass@1 单测）**或**语法解析器（AST / JSON dict）精确比对**。
  - 核心致命陷阱是**格式抽取失败与执行期崩溃**：多余的前后废话、缩进错乱、未导入库依赖、函数签名不一致或类型错误，哪怕逻辑大体正确也会直接得 0 分。
- **数据选择策略（可执行验证重于盲目堆量）**：
  - **执行过滤（Execution-filtered）是第一生命线**：宁要 20k~50k 条真实单测验证通过的样本，也不要 200k 未经校验的网络爬虫代码。对候选样本必须建立沙箱镜像：执行完整的“抽取 → 拼装 signature/docstring → 编译/运行单测”链路，剔除一切失败样本。
  - 优先选用带完整类型注解、标准 docstring 与清晰缩进的单函数实现；对于工具调用/结构化协议，强力过滤默认参数回显与类型不匹配样本。
- **训练目标与格式对齐**：
  - 采用全参 bf16 SFT，`max_seq_len=2048~4096`，`lr=1e-5~1.2e-5`。
  - **Prompt 全 mask，Completion-only 计算 loss**：训练文本必须与评测系统的 Chat 模板及代码块标记（如 fenced block 或 `<tool_call>`）逐字节对齐，并以合法 EOS 结尾。
- **进阶演进与 Model Soup（平滑方差）**：
  - 单阶段 SFT（通常 1~2 epoch 即可，小模型在高质量代码集上 1 epoch 往往已收敛绝大部分能力）。
  - **高分冲刺法（精选集小步长续训 + 权重插值）**：先在大底座代码集上打通基本语法（v1）；再挑选极高置信度、零污染的高分清洗子集，用极小学习率（`3e-6~4e-6`）进行小步长续训（v2）；最终将两阶段 Checkpoint 进行权重插值（如 `0.625·v1 + 0.375·v2`），能有效中和边界用例的单题波动，冲刺极致通过率。
- **解码决策**：
  - **坚决采用纯贪心（`temperature: 0.0`）**，显式写全双 EOS。代码与严格协议不需要随机性，任何轻微发散都会无谓增加语法与边界逻辑出错率。

**D. 选项式专业知识 / 科学推理**
- **任务形态与丢分本质**：
  - 输入通常为高难度专业领域（大学/研究生级数理化生、医学等）多选题，评测只提取最终选项字母（如 `ANSWER: X`）。
  - 两大核心丢分杀手：
    1. **长思维链（CoT）截断死循环**：小模型（4B）推理容易陷入车轱辘话与无限发散，70%+ 的生成可能因撞上长度上限（如 16k tokens）而永远无法输出答案标签，被判 0 分。
    2. **选项分布失衡（Position Bias）**：科学训练集中往往特定选项（如 B 占比过高）存在倾斜，导致小模型学会特定字母投机。
- **两条截然不同的高分路线与数据选择**：
  - **路线 1：长 CoT 蒸馏 + 选项平衡下采样（冲刺推理上限）**：
    - 选用顶尖长推理模型（如 R1 轨迹）蒸馏的科学选择题。
    - **严禁无脑打乱选项顺序**：因为长推理中往往已多次点名选项字母（如“分析可知A不合理，故选B”），打乱选项会导致轨迹逻辑与终答直接冲突；正确做法是**通过下采样平衡各选项（A/B/C/D 均衡）**。
    - 必须分层清洗：筛除过长、无限死循环的轨迹，保留最短正确推导路径。
  - **路线 2：纯答案直出 / 极简 SFT（稳健高性价比）**：
    - 实战经验表明，若小模型在长链发散上难以驾驭，完全可以反向破局：收集多源广泛的高质量科学 MCQ（20k~30k 条），监督目标直接设为最终答案（`completion-mode answer`），以 LoRA 或浅层 SFT 快速注入紧凑事实知识。小模型在此模式下耗时短、显存极省，且准确率往往能打平甚至超越控制不佳的长 CoT。
- **解码救命参数（长 CoT 下的胜负手）**：
  - **`repetition_penalty` 是长推理的关键生化武器**：若走长 CoT 路线，必须在 `generation_config.json` 中配置 `repetition_penalty ≈ 1.05~1.06`，搭配适度温度（0.6~0.9）。实战数据表明，这能直接将因复读导致的截断率从 77% 断崖式砸降至 4% 左右，直接逆转战局。
  - 短答案模式则坚决使用纯贪心（`temperature: 0.0`）。
- **选模与验证注意**：
  - 科学选择题通常样本量较小，方差大，绝对不可依赖 30~50 题的小子集下结论；此外，此类知识密集型任务中 Model Soup 有时会稀释高置信答案概率，必须以全量评测打过单模型为准，切勿盲信平均。

**E. 多轮专业、安全、健康或风险敏感回答**
- **任务形态与丢分本质**：
  - 输入为 5~11 轮的真实用户咨询上下文，最后一轮通常是复杂的诉求、模糊症状或高危情境；评测由强模型裁判按多维 Rubric（如事实严谨性、沟通边界、主动追问澄清、急症/风险分流、约束遵循）进行评分。
  - 核心痛点：基座模型在信息不充分时**倾向于武断盲猜而非反问澄清**，极易遗漏高危安全分流（如提示急诊就医），或输出套话严重缺乏深度。
- **数据与蒸馏策略（结构化合成 + 强教师自我反思）**：
  - **多轮矩阵情境合成**：使用 30B+ 教师模型，基于“主题 × 人设 × 语言 × 场景 × 意图转折”的笛卡尔网格合成真实多轮语境。**核心关键：前序轮次的助手发言应故意保留普通水平或轻微瑕疵**，还原真实人类对话的非完美历史。
  - **终轮强教师重写与自反思迭代**：末轮回答由强教师按照多维评分轴生成，并让教师对草稿执行“自审与临床/专业细节补充”，拉高回答的信息密度与严密性（如补充具体警示征象、生活干预与就医指引）。
  - **定向补丁数据（Patch Data）**：针对裁判重点扣分项（如缺少免责/急诊分流、缺少追问、特定格式忽略），定向注入 1k~2k 条强化遵循的高纯度补丁。
- **训练架构与阶段演进**：
  - **Masking 铁律**：**只对最后一轮 Assistant 计算 loss（Last-turn completion-only loss）**！坚决禁止对前序轮次的模拟弱回答计算 loss，防止模型逆向学会低质表达。
  - **轮数控制**：通常 2 个 epoch 即达最佳平衡；3 个 epoch 极易诱发对特定语调的过拟合，导致通用指令遵循能力暴跌。
  - **On-policy DPO + Model Soup 组合拳**：
    - 用 SFT 产出的模型进行多路采样，依据多维准则挑选成对样本（将啰嗦截断、漏掉澄清或漏掉安全分流的当 rejected）进行低学习率 DPO。
    - **`0.5·SFT + 0.5·DPO` 权重平均（Soup）**：SFT 擅长扎实的专业细节沉淀，DPO 擅长严苛的边界与格式遵循。将二者以 50/50 混合融合，在实战中屡屡能够斩获显著优于任一单模型的综合最高分。
- **解码策略**：
  - 优先选用低温贪心或极轻微随机（`temperature: 0.0~0.3`），确保格式合规与回答严肃性；显式写全双 EOS。

**F. 开放式、强约束写作与风格遵循**
- **任务形态与丢分本质**：
  - 面对开放域创意写作或复杂指令，由裁判模型进行双盲胜率（Win-rate）对抗。题目包含多语言环境与极其刁钻的正反向约束（字数区间、特定排版、禁用词、文学风格等）。
  - 三大核心败因：
    1. **恶性循环与无限续写**：长文生成中模型极易丧失停止感知，进入万 token 废话车轱辘循环，耗尽上限被判负。
    2. **语种与约束漂移**：面对多语言提示自动退化成英文；长篇大论后遗漏了初始的隐蔽约束。
    3. **教师人设与元话语泄露**：蒸馏时将教师的闲聊（“好的，为您创作如下...”）或 system prompt 污染进模型，引发机械做作感。
- **数据与蒸馏策略（脱壳蒸馏与多语言对齐）**：
  - **语种分布真实对齐**：若测试集存在显著的非英语（如 30% 覆盖中/日/西/德等），训练集中必须按相同比例覆盖多语言写作，不可依赖英文自发泛化。
  - **脱壳蒸馏（剥离教师脚手架）**：强教师（如 30B 写作模型）在带有优秀作家人设的 system prompt 驱动下生成高质量正文，但**在构造学生训练样本时，坚决将教师的 system prompt 与所有元话语剥离**！让学生模型学会在原生用户 prompt 下直接吐出高质正文。
  - **显式约束合成**：引入包含硬性负向与结构约束的合成题，培养小模型抵抗长度发散的能力。
- **偏好对齐（DPO 避坑指南）**：
  - **避免绝对打分**：强模型打分往往饱和在极窄高分区间，难以形成有效区分度。推荐采用**成对相对比较（Pairwise comparison）**：同一 prompt 采 4 个候选，由教师挑出相对最优与最劣构造 pairs。
  - DPO 适合仅做 1 轮低学习率对齐；过度轮次的 DPO 或高频自蒸馏（RAFT）容易导致小模型的生成多样性受损。
- **解码参数配置（抗长文本退化）**：
  - **引入适度重复惩罚（`repetition_penalty 1.05`）**：在开放长文本生成中，小模型极易陷入局部语义循环而无法自拔，最终耗尽生成预算。引入轻微的重复惩罚（`1.05` 左右）能有效打破死循环，保证篇章完整收尾与指令闭环，显著提升评测有效率。
  - 搭配中等温度与采样截断（`temperature: 0.7~0.8`、`top_p: 0.8~0.9`、`top_k: 20`），在保障文本自然流畅度的同时抑制极端发散。

## 4. 给定算力部署模型生产数据 (On-Device Data Generation)

### 4.1 合规红线与算力赋能边界
- **红线**：严禁调用任何外部商业闭源 API（如通过网络调用外部接口）。
- **允许且提倡**：**完全允许在当前任务分配的本地 GPU 算力中，拉起开源较强模型进行本地离线数据生产与处理**。在面对开放长文写作、复杂多轮对话、高质量科学与高难数学推理时，本地部署高阶模型自主生产高纯度训练集，是突破分数瓶颈的常规核心手段。

### 4.2 推荐模型选型与本地部署
- **推荐选型**：
  - 首选 **Qwen 系列 30B 级别的 FP8 官方量化版本**（可直接查阅参考 [Qwen HuggingFace Collections](https://huggingface.co/Qwen/collections)）。FP8 显存占用极低，在单张现代高显存卡（如 H100/A100）上即可轻松单卡拉起，且推断吞吐极高。
  - 针对特定专业领域，亦可选用对应垂直领域已验证的量化开源大模型（如 30B 级医疗/专业对话模型）。
- **部署方式**：
  - 必须采用高性能推理框架（如本地 `vLLM` 离线批处理引擎 `LLM.generate` 或本地单机 HTTP 服务），避免使用原生 PyTorch 循环前向，最大化榨干本地显卡吞吐。

### 4.3 典型任务下的生产范式（参考顶尖实战）
1. **开放长写作与风格遵循任务**：
   - **正文生成**：在本地 30B 模型上挂载强人设与结构要求的 System Prompt，批量输入清洗去重后的多语言种子 Prompt，离线高吞吐生成高质量长文。
   - **成对偏好标注（Pairwise DPO）**：使用训练出的学生模型对同一 Prompt 采样多个候选，直接调用本地 30B 部署的模型作为评判裁判，进行“A vs B 成对优劣对比”，生产数千对高区分度 DPO 数据。
2. **多轮专业对话与风险控制任务**：
   - **多轮矩阵情境构建**：使用本地大模型按照“主题 × 场景 × 角色”网格自动生成包含轻微瑕疵的 5~11 轮真实历史上下文。
   - **末轮自反思精修**：针对末轮复杂情境，先由本地大模型生成初版答复，再由模型自身执行第二遍“自审与临床/细节补全”，大幅提升答案的信息密度与严谨性。
3. **高难数学与确定性推理任务**：
   - **本地大模型生成多路轨迹**：针对题目集合，使用本地 30B 推理模型生成带有完整反思链条的解答。
   - **自身模型本地高并发采样（RFT / Rejection Sampling）**：在 SFT 阶段后，用模型自身在本地 vLLM 上对训练集进行高并发多路采样（如 k=8），程序化校验筛选出答案正确的多样化解题路径，混入后续训练以大幅强化能力。

### 4.4 数据门禁与清洗过滤（生产只是第一步，筛选决定上限）
本地模型生产出的海量原始数据绝不能直接塞入训练，必须经过严苛的程序化门禁管线：
- **脱壳清洗（剥离生成脚手架）**：
  - 生产时为了激发模型能力而附带的临时 System Prompt、引导语、以及模型吐出的客套闲聊（如“很高兴为您解答...”），在落盘为最终训练数据前**必须全部剥离**，只保留原生评测预期的 Input/Output 结构。
- **正确性与真值程序化硬校验**：
  - 对于带确定真值的任务（代码、数学、结构化输出），每条由本地模型产出的候选必须通过单元测试执行、AST 解析或严格数值正则比对；未通过校验的废案直接剔除。
- **长度门禁与死循环截断**：
  - 统计生成文本的 Token 分布，凡是触及本地模型生成上限、陷入局部词汇恶性复读的样本坚决丢弃，防止训练时向小模型注入长文本退化模式。
- **分布平衡与语言对齐**：
  - 检查生成的选项分布、语种分布及答案格式，必要时执行下采样以消除生成偏置。
