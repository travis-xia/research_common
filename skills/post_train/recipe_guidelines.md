# 训练方案与超参指南 (Recipe Guidelines)

## 何时查阅
- 在 Step0 汇总输出主干配方，或 Step2/3 构思训练相关的猜想与实验方案时，重要参考经验。

---

## 1. 训练范式选择
- **全参微调 vs LoRA/QLoRA**：
  - 若目标涉及“改变输出协议（如停止符行为、回答结构、思考标签格式）”或“深度任务推理能力提升”，优先采用全参微调（Full-parameter fine-tuning, bf16）。LoRA 常因未能充分调整词表/输出层而在协议对齐上失效。
  - 若显存受限或仅在极窄分布上做轻量模式注入，可使用 LoRA，但需密切监控格式遵循情况。
- **单阶段 vs 多阶段**：
  - 优先以稳定、高质量的 SFT 建立基准主干。
  - 在奖励函数高度明确、可程序化自动化验证（如数学终答、单元测试通过率）时，完全可以考虑引入 RL（比如GRPO） 阶段，使得模型收敛到正确分布。

---

## 2. 常用超参基准范围（经验先验）
- **学习率 (Learning Rate)**：
  - 全参 SFT：通常推荐在 `1e-5` 到 `2e-5` 之间，配合 Cosine 调度器与 3% Warmup。
  - LoRA：通常在 `1e-4` 到 `2e-4` 之间。
  - RL 阶段：学习率通常比 SFT 低一个数量级（`1e-6` 到 `3e-6`）。
- **训练轮数 (Epochs)**：
  - 绝大多数特定领域微调推荐 1 ~ 2 个 Epoch。
- **批次大小与吞吐优化（先大后小、爆显存再减半）**：
  - 有效 Batch Size 建议保持在 16 ~ 64。
  - **per-device bs 先大后小**：effective batch 定了之后，单卡批次（per-device bs）往大试（如从 8 或 16 起步），**真实爆显存（OOM）再减半**并成倍增加梯度累积步数（gradient_accumulation_steps）以补齐有效 batch。
  - 严禁凭空盲目把 bs 压得极小（吞吐大幅下降白白烧墙钟）。
  - 尽可能启用 FlashAttention-2 与 Gradient Checkpointing，词表大时使用 fused/chunked cross entropy 避免 logits OOM。
- **序列长度**：
  - `max_seq_len` 应根据目标任务协议的实际输入长度与最大生成上限总和反推，避免无意义的过大 padding 或粗暴截断。

---

## 3. 黄金初始策略示例（Golden Initial Strategy · 起手配方）

Step0黄金起手的核心原则是**先用最稳的配方跑通拿到基线，再谈改进**。以下先给不分难度的普适内核，再按任务难度分类讨论需要调整的旋钮。

### 3.1 普适内核（任何任务都照做）
- **范式**：单阶段全参微调（bf16），不要 LoRA/QLoRA。
- **格式对齐**（详见 `eval_alignment.md`）：训练样本与评测输入四层结构逐字节对齐；结尾固定「终答标记 + 立即停止符」（如 `ANSWER: <答案><|im_end|>`）；用 completion-only loss。
- **解码 `generation_config`**（详见 `inference_and_decoding.md`）：双 EOS 写全（如 Qwen `[151645, 151643]`），否则模型不停 → 0 分；`max_new_tokens ≥ 评测上限`（删掉基座默认 2048）；四采样键显式写全；存后复核未被回退成基座默认。
- **数据底线**：只留 verified-correct 样本、终答类型与评测一致；**务必对测试集做 8-gram/n-gram 去污染至重合度 0**（下面选数据的前提）。
- **流程纪律**：尽早存一个可用 `final_model` 兜底；下载/清洗与占卡训练并行；更长 trace、多阶段、RL 等改动**必须在 dev 上打过基线 SFT 才保留，打不过一律回退**。

### 3.2 按任务难度分类讨论（据此调整的旋钮）
先判断目标任务的难度与解答长度（看基线在评测上的行为、参考答案的推理步数），在下述两类间取值或插值：

**A. 难题 / 长推理（竞赛级数学、复杂多步推理与证明等）**
- **思维链**：蒸馏高质量**长思维链**，保留 `<think>…</think>` 标签（默认模板可能剥离，需手动保住）；同题多条正确 trace 时**取最短的正确 trace**并截到评测生成上限内。
- **序列长度**：适当取长，如`max_seq_len 8192~16384`，损失不大的情况下可以筛掉少量超长的先训练一个更大数据量、更高batch size的版本。
- **数据来源**：去污染前提下，优先**分布相近的高质量推理蒸馏集**（偏竞赛 / 奥赛级难题），规模约 **12k–32k 条**，数据尽量不要太少，可以从其他方面提高效率。
- **头号失败模式＝截断**：模型常话痨/复读/绕圈撑满上限却没吐出终答。对抗三板斧：最短正确 trace + `repetition_penalty 1.05` +（必要时）贪心；仍严重则追加一段更短更精炼的 SFT。
- **采样**：长 CoT 贪心易死循环，可用轻随机（如 Qwen3 thinking `temp 0.6 / top_p 0.95 / top_k 20`）。
- **RL**：时间/算力有限时收益有限，酌情。

**B. 简单题 / 短答案（基础应用题、格式化短输出等）**
- **思维链**：用**简短、有格式、有规划**的分步解题即可，**不需要长 `<think>`**，结尾直接 `ANSWER: <答案>`；过度冗长反而有害。
- **序列长度**：取短，`max_seq_len 1024~4096`，避免无谓墙钟。
- **数据来源**：去污染前提下，**尽量用该任务自身的官方训练集或相近题目**（官方 train 集 + 同源增广 / 改写数据），不必硬凑竞赛级数据；规模可更宽（数千原始 + 同源增广到数万）。
- **失败模式≠截断**：答案短、几乎不触顶；真正问题是「不停 / 跑题」，靠双 EOS + 贪心解决，一般**不需要 `repetition_penalty`**。
- **采样**：贪心（`temp 0`）即可，通常最稳。
- **RL**：奖励可程序化验证时 **RLVR/GRPO 收益大**（SFT 到瓶颈后常能再显著提点），值得在 SFT 后接一段。
