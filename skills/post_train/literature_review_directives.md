1. **读懂评测**：读评测代码，确定输出契约（标准答案 / 单测 / 精确匹配，还是 LLM 裁判、rubric、胜率）、题型与终答形式、是否带 system prompt 或 few-shot、生成上限。后面的检索与筛选都以此为准。
2. **反查最强公开方案**：找出目标基准（或同族基准）上，与 `{{MODEL}}` 同量级的模型公开过的最强 3 个左右后训练方案（技术报告、带 SFT 结果的数据集论文、模型卡、开源训练配置、复现 writeup）；另查目标基座同家族模型的 `generation_config.json`，不要混淆不同版本的分数。每个方案按下列字段抽取，原文没写的写「未报告」：
   - **结果**：基座与尺寸、目标基准分数、出处。
   - **数据**：来源、规模、构造或生成方式（生成模型的具体版本、prompt 从哪来）、过滤与筛选规则。
   - **训练**：方法与阶段顺序（全参 / LoRA、SFT / 偏好优化 / RL 等）、学习率与调度、epoch、有效 batch、总步数、序列长度。
   - **推理**：解码参数、生成上限。
   - **消融**：作者报告的哪些改动带来多少收益、哪些无效。
3. **调研数据候选（分数优先）**：在反查结果之外，按以下检索路线补全候选池，合并后再排序。候选池必须同时包含「直接使用公开数据的答案」和「用本机可部署模型重新生成答案」两类，按同样的字段写出来。
   - **公开数据**：按任务关键词检索数据集与论文；沿近 12–18 个月同类任务最强的开源模型（优先与 `{{MODEL}}` 同量级、从 Base 起训的），读其技术报告 / 模型卡的 post-training 数据章节，列出随模型开源或明确使用的数据集与子集；对每个经典数据集查有没有在同一任务上正面胜出的后继数据集（默认新一代优先，除非有反证）；一个数据集的题目取自另一个数据集、但用更强的模型重新生成并校验了答案时，它就是后者的后继；用 HF API 按 likes / downloads 翻持续开源后训练数据的机构页，例如 `curl -s "https://huggingface.co/api/datasets?author=<org>&sort=likes&direction=-1&limit=100"`（也可 `search=<领域词>`），org 例如 nvidia、allenai、open-thoughts、open-r1、HuggingFaceTB、a-m-team、Qwen、deepseek-ai 等。likes / 下载量高说明被社区复用和验证；几乎无人使用、也没有定量结果的放在后面。
   - **生成模型**：两条来源合并成候选清单。① 目标基准（没有就用最接近的基准）的公开排行榜，以及近期模型卡、技术报告里报告了该基准分数的模型，取分数最高的一批。② 逐个查主流开源模型家族的后训练模型，至少包括 Qwen、Gemma、Mistral，以及按任务关键词在 HF 上搜到的领域专用模型。每个家族用 HF API 列出该 org 的全部模型再按名称筛选，不靠记忆，也不要只看截断后的前几十条，例如 `curl -s "https://huggingface.co/api/models?author=<org>&limit=1000"`；带日期后缀的更新版、MoE 版、官方量化版都是不同版本，要分别读各自模型卡的分数。单卡 80GB 放得下（可用官方量化版，写明所用精度）、且 1–2 小时生成窗口内能产出足够条数的，列为本机生成候选；放不下或闭源的，查有没有用它生成的公开数据集。
   - **把每个候选拆成「prompt 来源 × 答案来源」**：prompt 来源看与评测的任务类型、语种、难度分布是否一致（评测分布从评测代码与基准公开说明获得，不读测试集），本机生成类要说明 prompt 来源与配比；答案来源写到具体模型版本。
4. **候选排序依据**：
   - **答案来源对比表**：模型能学到的上限受答案来源约束。把全部答案来源（公开数据集的生成模型、本机可部署的生成模型）放进同一张表；目标基座家族里每个比 `{{MODEL}}` 大、单卡放得下的后训练版本各占一行，其他家族至少列出各自最强的可部署版本。
     - 每行是一个具体版本，分数只能取该版本自己的模型卡、报告或榜单条目；名称相同但版本后缀、发布日期不同的是不同版本，旧版本的分数不能填给新版本。
     - 分数要同口径：同一基准、同一榜单或同一份报告，并写出该分数的生成上限与推理模式，与本评测明显不一致的不算同口径。比较两个答案来源时，用两者共同出现的来源比；某个模型不在某个榜单上，不能当作它弱的证据：要读它自己的模型卡补上分数，再找一个同时报告了它和对比对象的来源（另一个同时收录两者的榜单，或模型卡里列了对比对象的表）在同一基准上比；都找不到才写「未找到」。
     - 「是否已被超越」逐行核对：有没有发布更晚、同口径分数更高、且本机可部署（或已有公开数据）的答案来源，有就写出它的名称与分数。
     - 排序按同口径分数比较，不能用「闭源」「前沿」「知名」等印象代替分数；拿不出同口径分数的答案来源不能排第 1；已被超越的答案来源不能作主干。可校验任务还要看答案是否经过校验。
   - **有效条数**：预期分数由答案来源的水平和有效条数共同决定。公开数据看按过滤规则筛完后还剩多少条；本机生成按量级估算 1–2 小时生成窗口内可产出的合格条数，依据是总参数与激活参数（稠密 / MoE）、权重显存与剩余 KV 空间、平均输出长度；合格只计在本评测生成上限内完整收尾的样本，可校验任务还只计答对的样本。答案来源同口径分差在榜单误差内时，选可产出条数更多的；条数是否足够，参照反查方案的训练条数。
   - **与评测同形、分布一致**：题型、选项数、终答形式、难度、语种与任务类型覆盖与评测一致的数据作主干；不同形的只做补充。
   - **可归因的直接证据**：公开数据看「相同的 Base 只用该数据训练后，在目标基准或同族基准上的分数」；本机生成看生成模型自身在目标基准上的分数，以及反查方案中相近来源蒸馏的结果。两类证据形式不同，不能因为生成类没有训练后分数就排在后面。直接证据是加分项，不是必要条件。
   - **数据质量信号与规模可复现**：带逐样本质量信号（同题多解、校验结果、单测通过率、打分等）的优先；亮眼分数来自百万级样本或多阶段完整管线时，按本 run 单机条件打折。大数据集按子集使用。
   - **公开数据与本机生成的取舍**：先写出每个公开候选的答案来源及其同口径分数，再写出窗口内可部署的最强本机教师及其同口径分数。公开数据的答案来源不低于本机最强教师（或差距在榜单误差内），且过滤后条数不少于本机窗口内能产出的条数时，直接用公开数据；只有本机教师的同口径分数明显更高、且窗口内能产出的合格条数达到反查方案的训练条数量级时，本机生成才排第 1。
   - 第 1 位就是预期最终分数最高的组合，追求高分优先，不因下载更费时而降级（本机生成的耗时按上面的生成窗口算）；本机 HF 缓存只用来减少下载耗时，不作为排序优势。若第 1 位需要本机生成，第 2 位放一个可直接使用的公开数据作兜底。第 1 位必须就是第 5 步推荐方案的主干，两处不一致时按最终判断重排第 1 节。
   - **后继检查**：第 1 位是公开数据集时，马上做一次后继检查（可交给子 agent 与后续步骤并行）。用该数据集的名称做 HF 数据卡全文检索，例如 `curl -s "https://huggingface.co/api/search/full-text?q=<dataset-name>&type=dataset&limit=50&skip=<0,50,...>"`（只用名称比带 org 前缀的结果更集中，翻页看完）。去掉镜像与个人转存，只保留原机构或社区复用度高的条目（likes / downloads 以 `https://huggingface.co/api/datasets/<id>` 返回的为准），逐个读数据卡。若有数据集用的是**同一批题目**（或其超集）、换了更强的答案来源（同口径分数更高），且它自己的轨迹长度与格式能放进本评测的生成上限（按该数据集自己的数据卡或抽样判断，不套用其他数据集的情况），就直接替换第 1 位，原第 1 位降为兜底，不要求它另有直接证据；否则就不多做比较了；被替换后，对新的第 1 位再做一次同样的检查，直到没有更强的后继。把检查用的命令、找到的后继与比较结论写进报告。
5. **横向归纳与推荐方案**：写出多个方案共同采用或有消融支持的做法及数值范围与出处、方案间的分歧及各自成立的条件、在本 run 约束下哪些能直接复现、哪些要调整、哪些做不了。由此给出推荐方案：主干数据、数据构造流程、训练配置（学习率连同有效 batch 与步数）、解码设置、后续阶段的方法。
6. **失败现象反查**：同量级模型在这类任务上公开报告过的失败现象与修复办法，写最相关的 3–5 条，带数值与出处。
7. **边查边记**：开工 10 分钟内在 `{{CONTRACT_PATH}}` 写出第一版草稿，第 1 节要按当时的证据排好序（可标「暂定」，不能留「待定」），之后每有新证据就更新并重排，避免超时丢产物。每个数值都注明出处；找不到的写「未找到」，不要凭经验补数。
