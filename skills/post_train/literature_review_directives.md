0. **分工与并行**：第 1 步由主 agent 先做完，后面各步都依赖它的产物。第 2 步的三条调研线 2a / 2b / 2c 互不依赖，各交给一个子 agent 并行，主 agent 把第 1 步产物（评测画像）原样交给每个子 agent。第 3 步排序与第 4 步推荐方案需要同时看全部结果做判断，必须由主 agent 一人完成；后继检查是链式的，可在 2c 出结果后交给一个子 agent 与其余步骤并行。子 agent 把中间结果分别写到 `{{CONTRACT_PATH}}` 同目录的 `lit_teacher.md`、`lit_prompt.md`、`lit_public.md`，只有主 agent 写 `{{CONTRACT_PATH}}`。请多次查看时间，分配好时间，控制在1个小时以内完成调研。**子Agent的产物必须简洁明了，不得过于冗长，造成上下文过长、浪费时间**。
1. **评测画像（主 agent，重要串行前置）**：
   - **评测契约**：读评测代码，确定输出契约（max token 上限，标准答案 / 单测 / 精确匹配，还是 LLM 裁判、rubric、胜率，裁判模型与对手）、题型与终答形式、是否带 system prompt 或 few-shot、生成上限、是否剥离 `<think>`。如有research/protocol.md，可直接参考。
   - **基准介绍**：查该基准的论文、官方仓库、HF 数据卡与榜单说明（只读说明，不读测试集题目），明确写清：题目从哪来（来源平台、用户群、构造或筛选方式）、任务类型与子类占比、语种分布、难度与长度特征、评分维度；同族或前代基准、公开榜单地址，并列出前列模型。
   - **思考模式**：据契约判定训练目标是否保留教师的思考过程。答案可校验、靠长推理拿分且生成上限放得下完整推理的，可以保留完整 think；开放式问答、裁判打分、代码、工具调用等，用非思考直答。
   - 把以上写成一段「评测画像」，后续找相似数据集、选 prompt 池、定思考模式都以它为准。
2. **三条并行调研线**：答案找谁写、题目从哪来是两件独立的事，分开选优、最后再组合。注意反复关注agent的时间开销。
   - **2a 答案来源·本机生产数据**：只问在目标能力上谁最强，不管它将来用什么 prompt。按下面三步简洁明了列出候选：
     1. 枚举：对主流开源家族（含与 `{{MODEL}}` 同家族的开源org），直接用 HF API 列出该 org 的全部模型，例如 `curl -s "https://huggingface.co/api/models?author=<org>&num_parameters=min:3B,max:64B&limit=1000" | jq '[.[] | {id, createdAt}]'`，按名称筛出后训练版本（Instruct / Chat / Thinking 等）；不要只看截断后的前几十条。总参数如果没有在名字里的可用 `curl -s "https://huggingface.co/api/models/<id>?expand[]=safetensors"` 的 `safetensors.total` 查。
     2. 按本机可批量生成排除：本机单卡 80GB，总参数约 80B 及以上的直接排除，不再查分；排除禁止使用的模型。剩下的优先 MoE（激活参数小，性能好、推理快，1–2 小时窗口内才能产出足够条数），稠密模型只保留明显更强的少数。每个保留的候选写明生成时用的具体权重（优先官方量化版如 FP8 / AWQ / GPTQ-Int4，写出 repo id、精度、权重显存与剩余 KV 空间）。
     3. 按新旧与对口排重点：模型迭代快，同家族中发布日期更新的版本（带日期后缀的更新版、新一代）通常更强，重点关注、逐个读模型卡分数；带日期后缀的更新版、Instruct / Chat / Thinking 都是不同版本，分数不能互相套用。另外关注与目标基准业务特别对口的模型。
     每个候选写出：目标基准或对口能力上的分数（模型卡自报的注明「自报」）、按第 1 步定的思考模式、窗口内可产出的合格条数（依据总 / 激活参数、KV 空间、平均输出长度；只计在本评测生成上限内完整收尾的，可校验任务只计答对的）。放不下或闭源的强模型不作本机候选，交给 2c 查有没有用它生成的公开数据集。
   - **2b Prompt 池**：只问是否贴近评测画像，与答案来源无关。任何公开数据集的 prompt / 题目列都可以单独作为题源（原答案可丢弃），也包括真实用户对话日志、同族基准的训练集、任务对口的题库。按任务关键词在 HF 检索，例如 `curl -s "https://huggingface.co/api/datasets?search=<领域词>&sort=likes&direction=-1&limit=100"`。每个来源写出：与评测画像在任务类型与子类、语种、难度、长度上的匹配程度；去重过滤后的可用条数；与评测题目同源重叠的风险（只看来源说明，不读测试集）；许可。最后给出推荐的来源组合与配比。
   - **2c 公开方案与公开成品数据**：
     - **1. 反查最强公开方案**：找出目标基准（或同族基准）上，与 `{{MODEL}}` 同参数规模的模型公开过的最强 3 个后训练方案（技术报告、带 SFT 结果的数据集论文、模型卡、开源训练配置、复现 writeup）作为参考；另查目标基座同家族模型的 `generation_config.json`，不要混淆不同版本的分数。每个方案按下列字段抽取，原文没写的写「未报告」：
       - **结果**：基座与尺寸、目标基准分数、出处。
       - **数据**：来源、规模、构造或生成方式（生成模型的具体版本、prompt 从哪来）、过滤与筛选规则。
       - **训练**：方法与阶段顺序（全参 / LoRA、SFT / 偏好优化 / RL 等）、学习率与调度、epoch、有效 batch、总步数、序列长度。
       - **推理**：解码参数、生成上限。
       - **消融**：作者报告的哪些改动带来多少收益、哪些无效。
     - **2. 公开成品数据**：按任务关键词检索数据集与论文；沿近 12–18 个月同类任务最强的开源模型（优先与 `{{MODEL}}` 同量级、从 Base 起训的），读其技术报告 / 模型卡的 post-training 数据章节，列出随模型开源或明确使用的数据集与子集；对每个经典数据集查有没有在同一任务上正面胜出的后继数据集（默认新一代优先，除非有反证）；一个数据集的题目取自另一个数据集、但用更强的模型重新生成并校验了答案时，它就是后者的后继；用 HF API 按 likes / downloads 翻持续开源后训练数据的机构页，例如 `curl -s "https://huggingface.co/api/datasets?author=<org>&sort=likes&direction=-1&limit=100" | jq '[.[] | {id, createdAt, likes, downloads}]'`，org快速从各处获取：① 上面「反查最强公开方案」中出现的机构及其所用数据集的发布机构；② 「评测画像」中榜单前列模型的所属机构；③ 前面检索中反复出现的机构；④ 可自行补充其他著名开源机构。likes / 下载量高说明被社区复用和验证；几乎无人使用、也没有定量结果的放在后面。每个数据集写出答案来源（具体模型版本）、规模、格式（是否含 think、轨迹长度能否放进本评测生成上限），以及按评测画像判断的同形程度（任务子类、语种、难度、单轮 / 多轮是否一致，一致子集约多少条）；它的 prompt 列同时转交 2b 作为候选题源。
3. **候选排序（主 agent）**：
   - **答案来源对比表**：模型能学到的上限受答案来源约束。把 2a 的本机教师与 2c 公开数据集的生成模型放进同一张表；目标基座家族里每个比 `{{MODEL}}` 大、单卡放得下的后训练版本各占一行，其他家族至少列出各自最强的可部署版本。
     - 每行是一个具体版本，分数只能取该版本自己的模型卡、报告或榜单条目；名称相同但版本后缀、发布日期不同的是不同版本，旧版本的分数不能填给新版本。
     - 分数要同口径：同一基准、同一榜单或同一份报告，并写出该分数的生成上限与推理模式，与本评测明显不一致的不算同口径。比较两个答案来源时，用两者共同出现的来源比；某个模型不在某个榜单上，不能当作它弱的证据：要读它自己的模型卡补上分数，再找一个同时报告了它和对比对象的来源（另一个同时收录两者的榜单，或模型卡里列了对比对象的表）在同一基准上比；都找不到才写「未找到」。
     - 「是否已被超越」逐行核对：有没有发布更晚、同口径分数更高、且本机可部署（或已有公开数据）的答案来源，有就写出它的名称与分数。
     - 排序按同口径分数比较，不能用「闭源」「前沿」「知名」等印象代替分数；已被超越的答案来源不能作主干。可校验任务还要看答案是否经过校验。大模型发展迅速，存在时间代际差距时，通常以更新的模型整体能力更强。
   - **两条路线的组合与取舍**：本机路线 = 2a 最强本机教师 × 2b 推荐 prompt 池，按第 1 步定的思考模式生成；公开路线 = 2c 的公开成品数据原样使用。
     - **先过同形门槛**：公开路线原样使用，它的 prompt 与答案格式就是它自带的，所以先按 2b 的标准把它和评测画像比：任务类型与子类、语种、难度与长度是否一致，答案格式（是否含 think、终答形式、单轮 / 多轮、轨迹长度能否放进生成上限）是否符合第 1 步的契约与思考模式。不一致的公开数据，答案来源再强也不能原样作主干：能筛出一致子集且条数达到训练量级的，写清楚只用子集。一定要抽选真实题目和回答查看，确保尽量贴合基准任务题型。
     - **再比答案来源**：过了门槛的公开路线与本机路线在 prompt 分布上已可比，此时只比答案来源。本机教师不低于公开数据的答案来源（或差距在误差内）时，本机路线排第 1，公开路线第 2 作兜底；公开数据的答案来源同口径明显更高时，公开路线排第 1。
   - **有效条数**：预期分数由答案来源的水平和有效条数共同决定。条数达到反查方案的训练条数量级即为足够，公开数据条数更多不构成排序优势；答案来源分差在误差内时，才选可产出条数更多的。
   - **与benchmark同形、分布一致**：题型、终答形式、难度、语种与**任务类型**覆盖与benchmark画像一致的数据作主干；不同形的只做补充。
   - **可归因的直接证据**：公开数据看「相同的 Base 只用该数据训练后，在目标基准或同族基准上的分数」；本机生成看生成模型自身在目标基准上的分数，以及反查方案中相近来源蒸馏的结果。两类证据形式不同，不能因为生成类没有训练后分数就排在后面。直接证据是加分项，不是必要条件。
   - **数据质量信号与规模可复现**：带逐样本质量信号（同题多解、校验结果、单测通过率、打分等）的优先；亮眼分数来自百万级样本或多阶段完整管线时，按本 run 单机条件打折。大数据集按子集使用。
   - 第 1 位就是预期最终分数最高的组合，追求高分优先，不因下载更费时而降级（本机生成的耗时按 1–2 小时生成窗口算）；本机 HF 缓存只用来减少下载耗时，不作为排序优势。第 1 位必须就是第 4 步推荐方案的主干，两处不一致时按最终判断重排第 1 节。
   - **后继检查**：第 1 位或兜底是公开数据集时，对它做一次后继检查（交给子 agent 与其余步骤并行）。用该数据集的名称做 HF 数据卡全文检索，例如 `curl -s "https://huggingface.co/api/search/full-text?q=<dataset-name>&type=dataset&limit=50&skip=<0,50,...>"`（只用名称比带 org 前缀的结果更集中，翻页看完）。去掉镜像与个人转存，只保留原机构或社区复用度高的条目（likes / downloads 以 `https://huggingface.co/api/datasets/<id>` 返回的为准），逐个读数据卡。若有数据集用的是**同一批题目**（必须是模型卡里明确写了数据来源的，不可自行通过机构等判断）、换了更强的答案来源（同口径分数更高），且它自己的轨迹长度与格式能放进本评测的生成上限（按该数据集自己的数据卡或抽样判断，不套用其他数据集的情况），就直接替换，原数据集降为兜底，不要求它另有直接证据；否则就不多做比较了。把检查用的命令、找到的后继与比较结论写进报告。
4. **横向归纳与推荐方案（主 agent）**：写出多个方案共同采用或有消融支持的做法及数值范围与出处、方案间的分歧及各自成立的条件、在本 run 约束下哪些能直接复现、哪些要调整、哪些做不了。由此给出推荐方案：主干数据（答案来源、prompt 池与配比、思考模式）、数据构造流程、训练配置（学习率连同有效 batch 与步数）、解码设置、后续阶段的方法。
5. **边查边记**：第 1 步完成、子 agent 派出后，主 agent 立即在 `{{CONTRACT_PATH}}` 写出第一版草稿（评测画像 + 暂定排序，可标「暂定」，不能留「待定」）；每收到一条调研线的结果就更新并重排，避免超时丢产物。每个数值都注明出处；找不到的写「未找到」。
